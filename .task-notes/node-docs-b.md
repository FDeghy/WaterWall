## Feature-relevant observations

- RawSocket has `dont-capture-protocols` exclusion list only; a positive capture allowlist is absent in this description.
- Linux protocol exclusions use a fixed-size classic BPF predicate on IPv4 Protocol, applied to both NFQUEUE capture and incoming NOTRACK rules, including fragments and protocol zero; Windows uses `ip.Protocol` exclusions. This is the existing efficient kernel-filter seam.
- Capture source matching is independent of protocol matching. Filter port/protocol carefully to avoid intercepting unrelated genuine TCP from the same peer.
- Capture accepts unusual TCP flags, invalid TCP offsets and opaque transport bytes on Linux after exact IPv4 bounds checks. It preserves untrusted checksum bytes unless explicit pending-offload metadata requires safe repair.
- RawSocket receive capture limit is 1500 bytes. Raw output validates exact IPv4 length. Per-worker nonblocking batching supports up to 256 receive and 512 output packets per syscall without batch-fill delay.
- Packet-to-connection consumers must see restored complete IPv4/UDP rather than fake TCP if UDP semantics are desired. MUX, QUIC and normal TCP do not preserve UDP boundaries unless explicitly framed.
- Documentation conflict: RawSocket final fragment-policy paragraph says fragments reaching PTC are fatal; PTC own description says a bounded drop with diagnostic. Resolve against source; do not promote either to new contract on notes alone.
